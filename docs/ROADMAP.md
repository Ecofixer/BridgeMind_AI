# Founder + Company AI — Roadmap

## Phase 0 — Foundation

Delivered in this branch:

- clean founder/company product identity
- local structured memory
- tasks
- audit activity
- text chat
- push-to-talk capture
- optional transcription
- optional generative chat
- privacy-safe defaults
- typed architecture and tests

## Phase 1 — Trustworthy personal assistant

Build next:

- founder profile editor
- decision supersession and versioning
- reminders and due dates
- conversation threads
- memory approval before permanence
- import/export with encryption
- better bilingual voice commands
- compact daily briefing

Exit criteria:

- no duplicate memory
- decisions can supersede old decisions
- reminders have reliable timezone handling
- founder can see why context was selected

## Phase 2 — Company knowledge

Build:

- project registry
- document ingestion
- citations to source documents
- repository read access
- company policy library
- project status snapshots
- semantic retrieval after authorization filters

Exit criteria:

- every answer can identify its source
- founder-only content never appears in company retrieval tests
- stale data is labeled

## Phase 3 — Approval-based tools

Add read-only first:

- GitHub repository inspection
- calendar reading
- email search
- company files
- analytics

Then reversible writes:

- create branch
- create issue
- create draft
- create calendar hold

High-risk writes remain approval-gated:

- send email
- merge
- permission changes
- production changes
- payments

## Phase 4 — Company operating system

Build:

- employee accounts and role-based access
- approval inbox
- delegated work
- recurring workflows
- cross-project reporting
- operational dashboards
- audit export
- policy simulator

## Phase 5 — Realtime multimodal assistant

Build only after privacy controls are proven:

- realtime speech-to-speech
- optional wake word
- screen and camera understanding
- native mobile client
- desktop menu-bar client
- interruption and handoff
- low-latency tool use

## Priority rule

Do not add more agent names. Add capabilities behind one AI entry point.

Internal specialization is allowed only when it improves routing, testing, permissions, or reliability. It should not fragment the founder experience.
